# 1、Skill 数量增多，Agent 命中率如何保证？

先把「命中」定义清楚：该调用时选对 Skill，不该调用时不误触发。可以从四步入手：

1. **写清适用边界。** 描述 Skill 能做什么、什么时候用，以及哪些容易混淆的请求不该用。比如「我的订单到哪了」应该触发「查订单状态」，即使「取消订单」也包含“订单”这个关键词。
2. **缩小候选范围。** 可以按研发、运营等类别做粗筛。类别明确时优先查对应分区，类别不明确时允许跨类召回。再用关键词或语义检索找候选，对候选排序后取前 K 个。
3. **结合上下文做最终选择。** 让模型根据当前请求和对话上下文选 Skill。没有合适的候选时允许不调用，意图不明确时可以先问一句。
4. **用标注样本验证。** 用容易混淆的请求和无需调用 Skill 的请求做评估。看正确 Skill 有没有进前 K 个候选（Recall@K）、该调用时最终选对了多少，以及不该调用时有多少被误触发。命中率下降时，先区分是召回漏了，还是召回后选错了。

# 2、Agent的RAG遇到PDF，应该怎么处理？

**真实的PDF远比文字复杂**：
- **多栏排版**：文字顺序，穿插混乱
- **表格数据**：财务报表，统计图表
- **扫描件**：纸质图像，手写字体
- **页眉页脚**：干扰信息，噪声

可以从以下几步入手：
1. **页面向量化**：按照页面做图片Embedding，用问题向量和图片向量做匹配。[ColPali](https://arxiv.org/pdf/2407.01449)
2. **保留元信息**：切块后保留页码，页眉页脚信息。表格保留表头和标题。保留标题层级。
3. **给chunk保留上下文信息**：表明属于哪个章节，上下文在讲什么
4. **Agent工具链动态调用**：封装PDF工具集合，比如说我想找片段用search_PDF,具体读那一页面就用read_page,抽取表格用Extract——table，提取返回所有索引quote_source。简单事实就调用语意召回 xxx待补全具体场景
5. **避免幻觉**：强制UI带溯源功能，引用内容只能从给定的素材里面找，如果信息不足允许抛出问题，而不是自己幻觉。评测过程，需要去评测是否每次饮用都是正确的章节，命中正确的页码。
